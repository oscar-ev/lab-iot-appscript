IoT + Google Planilhas

Um ESP32 no Wokwi manda leituras direto para uma planilha do Google, sem servidor nem banco de dados. Depois a planilha ganha resumo, gráfico e até controla um LED.

Roteiro da aula. As etapas 1 a 3 são a atividade principal; as marcadas com + são complementos, um mais avançado que o outro.

Etapa 0

Visão geral: como o dado chega na planilha

Até agora usamos MQTT, em que um broker entrega as mensagens. Hoje o ESP32 vai falar direto com o Google, do mesmo jeito que o navegador abre um site: por HTTP.

ESP32 no Wokwi HTTP POST (JSON) Apps Script (Web App) Planilha
Google Planilhas
A planilha online do Google. É nela que as leituras vão aparecer, uma por linha.
Apps Script
Um lugar para escrever pequenos programas (em JavaScript) que mexem na planilha.
Web App
Quando o Apps Script é “publicado”, ele ganha um endereço na internet (URL). Quem acessa esse endereço faz o script rodar.
doPost
A função que roda quando alguém envia dados para a URL (pedido do tipo POST). Ela grava uma linha nova.
doGet
A função que roda quando alguém pede algo para a URL (pedido do tipo GET). Vamos usar no complemento de controle.
JSON
O formato da mensagem: {"sensor": "Temperatura", "valor": 25.3}.

MQTT ou HTTP direto?

MQTT (aulas anteriores)

Precisa de broker. A mensagem chega na hora, e vários sistemas podem ouvir ao mesmo tempo. Bom para controle em tempo real.

HTTP para a planilha (hoje)

Não precisa de broker nem servidor. Cada envio leva 1 a 3 segundos e vira uma linha guardada para sempre. Bom para registro e relatório.

O que você vai precisar

  • Uma conta Google pessoal (Gmail). Contas da instituição costumam bloquear a opção “Qualquer pessoa” da publicação.
  • Uma conta no Wokwi (pode entrar com a mesma conta Google).

Etapa 2

O Apps Script: a “porta de entrada” da planilha

  1. Abra o Apps Script

    Na planilha, menu Extensões → Apps Script. Abre uma aba nova com um editor de código. Clique em Projeto sem título, no alto, e dê o nome aula_iot_script.

  2. Cole o código

    Apague tudo o que estiver no arquivo Código.gs e cole:

    Código.gs (Apps Script)
    function doPost(e) {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheets()[0];
  var data = JSON.parse(e.postData.contents);
  var agora = new Date();
  sheet.appendRow([agora, data.sensor, data.valor]);
  return ContentService
    .createTextOutput("OK")
    .setMimeType(ContentService.MimeType.TEXT);
}

    Clique no ícone de disquete 💾 (Salvar projeto) ou aperte Ctrl + S.

    📖 Entenda o código (linha por linha)
    TrechoO que faz
    function doPost(e) { ... }Cria a função que o Google roda sozinho toda vez que alguém envia dados (POST) para a URL do Web App. O e é o “envelope” com tudo o que chegou.
    var ss = SpreadsheetApp.getActiveSpreadsheet();Pega a planilha onde o script está (a aula_iot_planilha) e guarda na variável ss.
    var sheet = ss.getSheets()[0];Da lista de abas, pega a primeira (posição 0). É a aba Dados.
    var data = JSON.parse(e.postData.contents);e.postData.contents é o texto que o ESP32 mandou, por exemplo {"sensor":"Temperatura","valor":25.3}. O JSON.parse transforma esse texto num objeto, para usar data.sensor e data.valor.
    var agora = new Date();Pega a data e a hora deste instante, no relógio do Google.
    sheet.appendRow([agora, data.sensor, data.valor]);Acrescenta uma linha no fim da aba, com três células: data/hora (coluna A), nome do sensor (B) e valor (C).
    ContentService.createTextOutput("OK")Monta a resposta que volta para quem enviou: o texto “OK”.
    .setMimeType(ContentService.MimeType.TEXT);Avisa que a resposta é texto simples (e não uma página HTML).
    Não use o botão Executar

    Não clique em Executar (▷) no editor. O doPost precisa de um pedido vindo de fora; rodando pelo editor aparece o erro Cannot read properties of undefined (reading 'postData'). Isso é normal e não quer dizer que o código está errado.

Deu algum erro?

A opção “Qualquer pessoa” não aparece

A sua conta é da instituição e ela só permite publicar para pessoas do mesmo domínio. Faça tudo (planilha + script) com uma conta Google pessoal (Gmail).

Aparece uma tela de login do Google em vez de “OK”

No PowerShell ou no navegador apareceu uma página do Google pedindo login. Confira se “Quem pode acessar” está em Qualquer pessoa. Se não estiver, faça Gerenciar implantações → Editar → mude → Nova versão → Implantar.

Abre uma página “Library Documentation” mostrando “doPost(Object e)”

Você copiou o link da Biblioteca (tem /macros/library/ no meio e termina em /1), e não o do App da Web. Vá em Implantar → Gerenciar implantações, clique na implantação App da Web e copie a URL que termina em /exec.

“Não foi possível abrir o arquivo neste momento” ou erro 404

A URL está incompleta ou é a do editor (termina em /edit). A certa termina em /exec. Copie de novo em Implantar → Gerenciar implantações.

A hora gravada está errada (adiantada ou atrasada)

A planilha está com o fuso de outro país. Na planilha: Arquivo → Configurações → Fuso horário → (GMT-03:00) Horário de Brasília. No Apps Script: ⚙️ Configurações do projeto → Fuso horário. Depois publique uma nova versão.

    main.py (MicroPython)

# --- CONFIGURAÇÃO Wi-Fi ---
SSID = "Wokwi-GUEST"
PASSWORD = ""

# --- LOOP PRINCIPAL ---
while True:

    valor = 25.3  # valor de exemplo

Deu algum erro?

Fica muito tempo em “Conectando ao Wi-Fi.......”

A demora é do simulador, não do código. O Wokwi-GUEST passa por um servidor gratuito do Wokwi, compartilhado por todo mundo, que fica lento em horários de muito uso (e com a turma toda conectando ao mesmo tempo). Espere até 1 minuto; se não conectar, clique em ⏹ e ▶ de novo; se continuar, salve e recarregue a página (F5). Não precisa mudar o código.

Aparece “Resposta: OK”, mas a linha demora a aparecer

O Google demora: cada envio leva de 1 a 3 segundos. Espere uns 20 segundos e atualize a planilha (F5). Se a resposta for OK, o dado chegou.

Resposta com um texto enorme em HTML, ou “Página não encontrada”

A URL no main.py está errada ou incompleta. Copie de novo (deve terminar em /exec) e cole entre as aspas.

Resposta com uma mensagem de erro do Google (“TypeError”, “Exception”)

O doPost deu erro. Abra o Apps Script → menu da esquerda, Execuções (ícone ☰ com relógio): o erro aparece lá, em vermelho. O mais comum é ter mudado o código e não ter publicado uma nova versão.

“Erro ao enviar: Redirects not yet supported”

A versão do MicroPython do projeto é muito antiga. Crie o projeto de novo pelo link do passo 1. Mesmo com esse aviso, confira a planilha: o dado costuma chegar.

A resposta é um HTML enorme terminando em “Script function not found: doGet”

O Google responde aos envios com um redirecionamento, e às vezes a resposta que volta para o ESP32 é esta página de aviso, e não o “OK”. Não atrapalha a gravação: confira a planilha. O aviso some no Complemento 3, que cria a função doGet.

“Erro ao enviar: (-29312, 'SSL - The connection indicated an EOF')”

A conexão segura (HTTPS) com o Google caiu. O Google atende em dois passos: primeiro roda o doPost e grava a linha, depois manda o ESP32 buscar a resposta “OK”. Quase sempre a queda acontece no segundo passo, então confira a planilha: a linha costuma estar lá. Por isso o código não tenta de novo (criaria linhas repetidas). Nos códigos dos complementos, o gc.collect() (libera memória) e a pausa de 2 segundos depois do Wi-Fi deixam esse aviso bem mais raro. Não diminua o intervalo do time.sleep para menos de 15 segundos: cada envio abre uma conexão HTTPS, e o ESP32 do simulador não dá conta de muitas seguidas.

“Erro ao enviar: [Errno 113]”, “-202”, “ECONNRESET” ou “MemoryError”

Falha momentânea de rede ou memória. O código tenta de novo sozinho na próxima volta. Se acontecer sempre, aumente o time.sleep(10) para 15.

Etapa 4 · Complemento 1

+ Um sensor de verdade (DHT22)

O valor 25.3 fixo não mede nada. Vamos ligar um DHT22, que mede temperatura e umidade, e mandar as duas leituras. O Apps Script não muda: cada leitura vira uma linha, com o nome do sensor na coluna B.

  1. Monte o circuito

    No Wokwi, clique no + azul e adicione um DHT22. Ligue: VCC → 3V3, SDA → 15, GND → GND.

    Já aproveite e coloque o que vai ser usado no Complemento 3: um LED verde com um resistor de 220 Ω: pino 26 → resistor → perna A do LED, e perna C → GND.

  2. Troque o código

    Apague o main.py e cole:

    main.py (MicroPython)
    import network
import urequests
import time
import dht
import gc
from machine import Pin

# --- CONFIGURAÇÃO Wi-Fi ---
SSID = "Wokwi-GUEST"
PASSWORD = ""
print("Conectando ao Wi-Fi...")
wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect(SSID, PASSWORD)
while not wlan.isconnected():
    print(".", end="")
    time.sleep(0.5)
print("\nWi-Fi conectado!")

# --- URL DO WEB APP ---
URL = "COLE_AQUI_A_URL_DO_WEB_APP"

# --- SENSOR ---
sensor_dht = dht.DHT22(Pin(15))   # DHT22 ligado no pino 15

def enviar(sensor, valor):
    dados = {"sensor": sensor, "valor": valor}
    gc.collect()                            # libera memória antes do HTTPS
    try:
        resposta = urequests.post(URL, json=dados)
        print("Enviado:", dados, " | Resposta:", resposta.text)
        resposta.close()
    except Exception as e:
        # O Google grava a linha ANTES de responder. Se a conexão cair
        # depois disso, o dado já está na planilha: só a resposta se perdeu.
        print("Aviso ao enviar", dados, ":", e, "(confira a planilha)")

# --- LOOP PRINCIPAL ---
while True:
    sensor_dht.measure()                          # faz a leitura
    enviar("Temperatura", sensor_dht.temperature())
    enviar("Umidade", sensor_dht.humidity())
    time.sleep(15)  # a cada 15 segundos (2 linhas por vez na planilha)
    📖 Entenda o código (linha por linha)
    TrechoO que faz
    import dhtBiblioteca do sensor DHT22 (temperatura e umidade).
    import gcO “coletor de lixo”: limpa da memória o que não é mais usado.
    from machine import PinTraz a classe Pin, que representa um pino do ESP32.
    time.sleep(2) (depois do Wi-Fi)Espera 2 segundos para a rede do simulador ficar pronta antes do primeiro envio.
    sensor_dht = dht.DHT22(Pin(15))Diz que há um DHT22 ligado no pino 15.
    def enviar(sensor, valor):Cria uma função: um bloco de código com nome, que pode ser chamado várias vezes com valores diferentes. Evita repetir o mesmo código para temperatura e umidade.
    gc.collect()Limpa a memória antes de cada envio, porque a conexão HTTPS gasta bastante.
    except ... print("Aviso ao enviar" ...)Se a conexão cair, avisa, mas lembra que o dado pode já estar na planilha: o Google grava antes de responder.
    sensor_dht.measure()Manda o sensor fazer uma leitura nova.
    sensor_dht.temperature() / humidity()Devolvem a temperatura (°C) e a umidade (%) da última leitura.
    enviar("Temperatura", ...) / enviar("Umidade", ...)Chama a função duas vezes: entram duas linhas na planilha.
    time.sleep(15)Espera 15 segundos. Menos que isso sobrecarrega o HTTPS do simulador.

    O envio virou uma função, enviar(sensor, valor), chamada duas vezes: assim não repetimos o mesmo código. Também entraram o gc.collect(), que libera memória antes de cada envio (o HTTPS gasta bastante), e uma pausa de 2 segundos depois do Wi-Fi.

Etapa 5 · Complemento 2

+ Uma planilha inteligente: resumo, cores e gráfico

Agora a planilha trabalha sozinha: calcula estatísticas, pinta os valores altos e desenha um gráfico, tudo atualizado a cada leitura que chega.

Antes de colar as fórmulas

Use ponto e vírgula (;) entre os argumentos, como está aqui. Se a sua planilha estiver em inglês e der erro, troque por vírgula (,) ou mude em Arquivo → Configurações → Localidade → Brasil. As fórmulas estão com o nome em inglês porque funcionam em qualquer idioma; o Google pode traduzir sozinho (AVERAGEIF vira MÉDIASE, por exemplo). É normal.

Parte A: a aba de resumo

  1. Crie a aba “Resumo”

    Lá embaixo, clique no + (Adicionar página). Clique com o botão direito na aba nova → Renomear → Resumo. A aba Dados precisa continuar sendo a primeira.

  2. Escreva os nomes e cole as fórmulas

    Em cada linha, escreva o nome na coluna A (por exemplo, em A1 só Última temperatura) e cole a fórmula na coluna B da mesma linha:

    NºEscreva na coluna ACole na coluna B
    1Última temperatura=INDEX(FILTER(Dados!C:C;Dados!B:B="Temperatura");COUNTIF(Dados!B:B;"Temperatura"))
    2Média=ROUND(AVERAGEIF(Dados!B:B;"Temperatura";Dados!C:C);1)
    3Máxima=MAXIFS(Dados!C:C;Dados!B:B;"Temperatura")
    4Mínima=MINIFS(Dados!C:C;Dados!B:B;"Temperatura")
    5Nº de leituras=COUNTIF(Dados!B:B;"Temperatura")
    6Acima de 30 °C=COUNTIFS(Dados!B:B;"Temperatura";Dados!C:C;">30")
    FórmulaO que faz
    COUNTIF (CONT.SE)Conta quantas linhas da coluna B são “Temperatura”.
    AVERAGEIF (MÉDIASE)Faz a média da coluna C, só nas linhas de “Temperatura”.
    MAXIFS / MINIFSMaior e menor valor da coluna C, só de “Temperatura”.
    FILTER + INDEXSepara só as temperaturas e pega a última da lista.
    COUNTIFS (CONT.SES)Conta com duas condições: é temperatura e passou de 30.
    Confira

    Os números aparecem na hora e mudam sozinhos a cada leitura nova. Mude a temperatura no DHT22 para 35 °C e veja a máxima e o “Acima de 30” mudarem.

Parte B: cores automáticas

  1. Selecione a coluna dos valores

    Volte para a aba Dados e clique na letra C, no alto da coluna.

  2. Crie a regra

    Menu Formatar → Formatação condicional. No painel da direita, em Regras de formatação, escolha A fórmula personalizada é e cole:

    Fórmula personalizada

Parte C: o gráfico

A aba Dados mistura temperatura e umidade, o que deixaria o gráfico confuso. Primeiro separamos só as temperaturas.

  1. Separe as temperaturas

    Na aba Resumo, clique na célula D1 e cole:

    Célula D1 da aba Resumo
    =QUERY(Dados!A:C;"select A, C where B = 'Temperatura'";1)

    O QUERY funciona como uma pergunta ao banco: “me dê a data (A) e o valor (C) das linhas em que o sensor (B) é Temperatura”. As colunas D e E se enchem sozinhas.

  2. Insira o gráfico

    Selecione as colunas D e E (clique na letra D e arraste até a E). Menu Inserir → Gráfico. No painel da direita (Editor de gráficos), em Tipo de gráfico, escolha Gráfico de linhas.

    Ainda no Editor de gráficos, lá embaixo, marque Usar a coluna D como rótulos. Assim a data e hora vão para o eixo de baixo (eixo X), em vez de virar uma segunda linha.

    Apareceram duas linhas (azul e vermelha)?

    O Google tratou a Data/Hora como valor. Marque Usar a coluna D como rótulos; se a linha extra continuar, em Série clique nos três pontinhos ao lado de Data/Hora → Remover.

    Confira

    Aparece uma linha: a temperatura ao longo do tempo, com as horas no eixo de baixo. Ela ganha um ponto novo a cada leitura.

Desafio

    ss.getSheetByName("Dados")Agora a planilha tem várias abas, então buscamos a aba pelo nome, e não pela posição. O nome precisa ser exatamente igual.
    function doGet(e) { ... }A função que o Google roda quando alguém faz um pedido GET na URL: quando o ESP32 pergunta, ou quando você abre a URL no navegador.

  4. Atualize o código do ESP32

    Confira se o LED do Complemento 1 está no circuito (pino 26) e cole o novo main.py:

    main.py (MicroPython)
    import network
import urequests
import time
import dht
import gc
from machine import Pin

# --- CONFIGURAÇÃO Wi-Fi ---
SSID = "Wokwi-GUEST"
PASSWORD = ""
print("Conectando ao Wi-Fi...")
wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect(SSID, PASSWORD)
while not wlan.isconnected():
    print(".", end="")
    time.sleep(0.5)
print("\nWi-Fi conectado!")

# --- URL DO WEB APP ---
URL = "COLE_AQUI_A_URL_DO_WEB_APP"

# --- SENSOR E ATUADOR ---
sensor_dht = dht.DHT22(Pin(15))   # DHT22 no pino 15
led = Pin(26, Pin.OUT)            # LED (com resistor) no pino 26

def enviar(sensor, valor):
    dados = {"sensor": sensor, "valor": valor}
    gc.collect()                            # libera memória antes do HTTPS
    try:
        resposta = urequests.post(URL, json=dados)   # POST = gravar
        print("Enviado:", dados, " | Resposta:", resposta.text)
        resposta.close()
    except Exception as e:
        # O Google grava a linha ANTES de responder. Se a conexão cair
        # depois disso, o dado já está na planilha: só a resposta se perdeu.
        print("Aviso ao enviar", dados, ":", e, "(confira a planilha)")

def ler_comando():
    # Pedir o comando não grava nada, então pode tentar de novo sem problema
    for tentativa in range(2):
        gc.collect()
        try:
            resposta = urequests.get(URL)             # GET = perguntar
            comando = resposta.text.strip()
            resposta.close()
            return comando
        except Exception as e:
            print("Erro ao ler comando (tentativa", tentativa + 1, "):", e)
            time.sleep(2)
    return None                                       # não conseguiu: LED fica como está

# --- LOOP PRINCIPAL ---
while True:
    sensor_dht.measure()
    enviar("Temperatura", sensor_dht.temperature())
    enviar("Umidade", sensor_dht.humidity())

    comando = ler_comando()
    print("Comando da planilha:", comando)
    if comando == "ON":
        led.value(1)
    elif comando == "OFF":
        led.value(0)

    time.sleep(15)
    📖 Entenda o código (linha por linha)
    TrechoO que faz
    led = Pin(26, Pin.OUT)O pino 26 vira uma saída: o ESP32 consegue ligar (1) e desligar (0) o LED.
    def ler_comando():Função que pergunta à planilha qual é o comando.
    urequests.get(URL)Faz um pedido GET: é ele que faz o doGet rodar no Google. POST é para mandar dados; GET é para pedir.
    resposta.text.strip()Pega o texto da resposta e tira espaços e quebras de linha.
    for tentativa in range(2):Tenta pedir o comando até 2 vezes. Aqui pode repetir sem medo, porque o GET só pergunta e não grava nada. (No envio, repetir criaria linhas duplicadas.)
    return comando / return NoneDevolve o comando lido. Se as duas tentativas falharem, devolve None (nada), e o LED fica como está.
    if comando == "ON": led.value(1)Se a planilha disse ON, acende o LED.
    elif comando == "OFF": led.value(0)Senão, se disse OFF, apaga. Qualquer outra coisa não muda o LED.

★ Desafio: alerta por e-mail

Quando a temperatura passar de 35 °C, o próprio Apps Script manda um e-mail de alerta para os professores, com o seu nome. Para não encher a caixa de entrada, ele manda no máximo um e-mail a cada 10 minutos.

  1. Troque o script inteiro

    No Apps Script, apague tudo e cole o script completo abaixo. Ele é o mesmo do Complemento 3 (doPost + doGet), com o alerta acrescentado dentro do doPost, no bloco marcado NOVO: ALERTA POR E-MAIL:

    Código.gs completo (Apps Script)
    function doPost(e) {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName("Dados");          // aba das leituras
  var data = JSON.parse(e.postData.contents);
  var agora = new Date();
  sheet.appendRow([agora, data.sensor, data.valor]);

  // ---- NOVO: ALERTA POR E-MAIL ----
  var DESTINOS = "alessandrohoras@umc.br, oscarevangelista@umc.br";
  var ALUNO = "COLOQUE AQUI SEU NOME E TURMA";
  if (data.sensor == "Temperatura" && data.valor > 35) {
    var memoria = PropertiesService.getScriptProperties();
    var ultimo = Number(memoria.getProperty("ultimoAlerta") || 0);
    var dezMinutos = 10 * 60 * 1000;
    if (Date.now() - ultimo > dezMinutos) {        // no máximo 1 e-mail a cada 10 min
      MailApp.sendEmail(
        DESTINOS,                                  // para os professores
        "Alerta IoT (" + ALUNO + "): temperatura alta",
        "Aluno(a): " + ALUNO + "\nA temperatura chegou a " + data.valor + " °C em " + agora
      );
      memoria.setProperty("ultimoAlerta", String(Date.now()));
    }
  }

  return ContentService
    .createTextOutput("OK")
    .setMimeType(ContentService.MimeType.TEXT);
}

Limites e boas práticas

  • O Google limita quantas vezes por dia um script pode rodar e enviar e-mails. Para estudo, não chega perto, mas evite intervalos menores que 10 segundos.
  • Uma planilha aguenta muitas linhas, mas fica lenta com centenas de milhares. Para projetos que rodam 24 horas por dia, o caminho é um banco de dados, como na aula da estação meteorológica.
  • A URL do Web App funciona como uma senha. Se ela vazar, faça uma Nova implantação (gera outra URL) e arquive a antiga em Gerenciar implantações.
